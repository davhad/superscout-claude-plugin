# Manage venture scouting

Use the authenticated user's own Superscout workspace. Begin by reading the
current Scout declaration, investment preferences, relevant lists, follows,
and private organization records. Do not overwrite an existing thesis or list
without showing the current value and the proposed change.

Keep these concepts distinct:

- A persona is self-declared context, not a verified role.
- A Scout declaration records motivation, edge, sectors, regions, stages,
  sourcing channels, compensation expectations, and capacity. It grants no
  authority or entitlement.
- An investment preference is a private personal thesis with a currency and
  whole-unit ticket range.
- A private organization is visible only to the connected user and does not
  create or edit a canonical Superscout organization.
- A list organizes known visible targets. A follow records desired retention
  state only and does not enable alerts.

When the user wants a workspace review, summarize gaps and inconsistencies
without changing anything. When they approve a change, use the narrowest tool
and confirm the returned state. Do not expose operator research, canonical
sync, approval, publication, admin, billing, or bulk-export workflows.
